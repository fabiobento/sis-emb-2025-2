O que é Machine Learning?

Machine Learning é a ciência (e arte) de programar computadores para que possam **aprender com dados**, sem serem explicitamente programados para cada regra. Vamos ver a diferença com um exemplo clássico: um filtro de spam.

Abordagem Tradicional

  • Estudar o problema e identificar palavras-chave ("grátis", "promoção").
  • Escrever regras explícitas para cada padrão.
  • Manter manualmente uma lista complexa e crescente de regras.
  • Resultado: Rígido, difícil de manter e lento para adaptar.

Abordagem de Machine Learning

  • Alimentar o algoritmo com exemplos de spam e e-mails normais.
  • O modelo **aprende automaticamente** os padrões que indicam spam.
  • Adapta-se a novos tipos de spam sem intervenção manual.
  • Resultado: Preciso, flexível e fácil de manter.

Tipos de Sistemas de ML

Os sistemas de ML são categorizados principalmente pelo nível de supervisão humana durante o treinamento e pela sua capacidade de aprender de forma incremental.

Por Nível de Supervisão

Supervisionado

Aprende com dados rotulados. O objetivo é prever um rótulo (classificação) ou um valor (regressão).

Não Supervisionado

Aprende com dados não rotulados. O objetivo é descobrir estruturas ocultas, como grupos (clustering) ou anomalias.

Semi-supervisionado

Usa uma mistura de muitos dados não rotulados e poucos dados rotulados.

Por Reforço

Um "agente" aprende a tomar decisões através de um sistema de recompensas e penalidades, interagindo com um ambiente.

Por Capacidade de Aprendizado

Em Lote (Batch)

Treina com todos os dados disponíveis de uma vez. Para se adaptar, precisa ser treinado do zero novamente.

Online

Aprende de forma incremental, com mini-lotes de dados. Ideal para sistemas que precisam se adaptar rapidamente.

Desafios Principais em ML

O sucesso de um projeto de ML depende de superar dois grandes obstáculos: dados de má qualidade e modelos inadequados.

Desafios com os Dados

  • Quantidade Insuficiente: A maioria dos algoritmos precisa de muitos dados para aprender.
  • Não Representativos: Dados de treino que não refletem a realidade levam a previsões ruins.
  • Qualidade Baixa: Erros, outliers e ruído podem confundir o modelo.
  • Atributos Irrelevantes: "Lixo entra, lixo sai". A Engenharia de Atributos é crucial.

Desafios com os Modelos

  • Sobreajuste (Overfitting): O modelo decora os dados de treino, mas não generaliza para novos dados. É complexo demais.
  • Subajuste (Underfitting): O modelo é simples demais e não consegue capturar a estrutura dos dados.

Teste e Validação

Para garantir que nosso modelo seja realmente bom, e não apenas um bom "decorador" de dados, dividimos nosso conjunto de dados de forma estratégica.

Conjunto de Treinamento
~80% - Usado para ensinar o modelo.
Conjunto de Validação
~10% - Usado para ajustar hiperparâmetros.
Conjunto de Teste
~10% - Usado **apenas no final** para a avaliação final.

Regra de Ouro: Nunca olhe para o conjunto de teste durante o desenvolvimento. Isso evita o *data snooping* e garante uma estimativa honesta do desempenho do modelo no mundo real.
